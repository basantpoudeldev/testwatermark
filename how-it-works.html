How Proofmark works

Everything happens in your browser. Here's what that actually means, technically.

No server ever touches your files

Most watermarking or compression tools work by uploading your file to a server, processing it there, and sending the result back. Proofmark doesn't do this. Instead, it uses your browser's own built-in capabilities — the same engine that renders web pages — to do the actual image, PDF, and video processing on your device.

The tools under the hood

  • Images use the HTML5 Canvas API to draw your photo and the watermark pattern pixel-by-pixel, entirely client-side.
  • PDFs use an open-source library called pdf-lib to stamp, merge, split, sign, and edit PDFs directly in their vector layer, so text stays selectable and searchable in the output — it's not just a flattened image.
  • Video uses ffmpeg.wasm, a build of the open-source FFmpeg project compiled to WebAssembly, so it can run inside the browser rather than needing a server-side video pipeline.

Self-hosted, not CDN-dependent

Every library this tool relies on ships as part of Proofmark's own files rather than being fetched from a third-party CDN each time you visit. That means loading the tool doesn't quietly trust an external content network with every visitor's connection — there's simply one fewer party in the loop.

Why this matters

Beyond privacy, running everything client-side means Proofmark has no per-file processing cost, no upload wait time bottleneck, and no server capacity to run out of. It also means the tool keeps working even with a flaky connection, since nothing after the initial page load requires the internet.

Batch processing

Upload multiple files at once and the same watermark, crop, or compression settings apply to all of them. Results are bundled into a single ZIP download for images and PDFs.
